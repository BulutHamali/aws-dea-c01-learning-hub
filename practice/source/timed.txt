stem: A sequencing facility streams instrument events into AWS. An alerting application and a billing application read the same events independently. After a 30-hour outage, the alerting application must reprocess everything it missed. The team wants the least custom code. Which ingestion design meets these requirements?
A: Amazon Data Firehose delivering to S3, with both applications reading the new S3 objects || Firehose keeps no consumer positions. Each application would need its own code to track which objects it has read.
B: One SQS standard queue that both applications poll, with long polling turned on || Consumers of one queue compete for messages, and a deleted message cannot be read again.
C: Kinesis Data Streams with retention above 30 hours and one consumer per application || Each consumer keeps its own position, and retention longer than the outage allows replay.
D: Kinesis Data Streams with default retention and enhanced fan-out for both applications || Enhanced fan-out adds read bandwidth, but the 24-hour default retention expires part of the 30-hour gap.
explain: Replay and independent readers point to Kinesis Data Streams. The deciding detail is the 30-hour outage, which is longer than the 24-hour default retention.

A: GROUP BY sensor_id and day, then compute AVG(reading) across the seven most recent days || Grouping collapses rows. It returns aggregates instead of each detail row with its own moving average.
B: Compute AVG(reading) OVER (PARTITION BY sensor_id) with no ORDER BY and no window frame || Without ordering and a frame, every row gets the sensor's overall average, not a seven-day average.

explain: Keeping detail rows while adding a calculation over neighbouring rows is exactly what a window function does.
